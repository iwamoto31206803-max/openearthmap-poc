# OpenEarthMap PoC — GT54 evaluator 設計レビュー／実装計画

> **用途:** この文書は、`docs/GT54_EVALUATION_PROTOCOL.md` を既存実装と照合した検討結果を、メインチャットへそのまま返すための回答本文です。実装済み機能の説明ではなく、現状評価と今後の実装計画を示します。
>
> **レビュー対象:** `src/evaluation/`、`tools/evaluation/`、GT54 dataset builder、既存推論処理、関連テスト、および `manifests/val_gt_georef.csv`。このレビューでは evaluator のコード変更は提案のみで、実装は行っていません。

## 結論

既存 repository には、raster alignment、OEM8 値域検証、9×9 prediction transition、A/B/C/D への共通入力、checkpoint SHA256 記録など、GT54 evaluator に再利用できる周辺部品がある。一方、正式仕様の中核である GT 基準 metrics、NoData mask、absent class rule、spatial de-duplication、GT_CONFLICT、owner map、Equal-region Macro、formal comparisons は未実装である。

既存 comparison script を巨大化させず、`src/evaluation/` に reusable core、`tools/evaluation/` に薄い CLI を新設する。最初の実装は dataset/grid preflight と canonical pixel identity に限定し、実 GT54 が lossless common lattice を構成できることを確認してから metric と比較処理へ進む。

## A. Repository assessment

### GT54 dataset / manifest

- 正式 manifest `manifests/val_gt_georef.csv` は `valarea,year,region` の54行で、composition の正として使える。
- `src/build_gsi_val_gt54.py` はこの3列を検証し、ValArea 重複を拒否する。
- builder がローカル生成する `<dataset-root>/manifest.csv` には RGB/GT path、CRS、shape、transform、bounds、SHA256、`alignment_ok` が含まれる。正式 manifest とローカル inventory は役割を分ける。
- builder は RGB を GT grid へ bilinear reprojectする一方、GT はコピーのみで resample しない。
- RGB/GT の band数、width/height、CRS、transform、bounds、GT class 0–8 の検証は再利用可能。ただし evaluator 共通 core へ整理するのが望ましい。

### `src/evaluation/`

現状は SACLAJ の point/patch-based evaluation が中心で、GT54 full-scene segmentation とは責務が異なる。SHA256、厳密な CSV schema validation、paired input、run status/manifest の考え方は再利用できるが、GT54 core として直接拡張しない。

### `tools/evaluation/compare_classification_rasters.py`

再利用可能:

- `width / height / CRS / transform` の完全一致検証
- OEM8 class ID 0–8 の値域検証
- `np.add.at` による 9×9 transition matrix
- class 0 を含む81セルの保持
- pixel-aligned AOI validation

不足:

- matrix は prediction-before → prediction-after であり、GT → prediction confusion ではない
- NoData、Background primary exclusion、absent class、metrics、de-dup、GT-conditioned transition がない

### `compare_classification_progression.py`

4 stage wrapper と output namespace は再利用できる。ただし現在は隣接3比較だけであり、正式5比較の A→C、A→D がない。また GT を入力しないため correction/regression は算出できない。

### `compare_teacher_progression.py`

最も近い既存実装であり、次を再利用できる。

- Base / Paddy / Paddy+Water / Paddy+Water+Road の4 stage
- 同一 RGB を全 checkpoint に使用
- prediction alignment と class range validation
- checkpoint hash、preprocessing、software version、inference parameters の記録
- 9×9 prediction transition、fixed/top transition の実装パターン
- output/overwrite safety

ただし formal evaluator が raw argmax と sieve のどちらを使うかは未確定である。推奨は raw argmax を formal、sieve を optional diagnostic とすること。

### `compare_base_ft.py`

streaming SHA256、subprocess failure propagation、paired-raster alignment、transition matrix、timestamps/software versions は再利用できる。GT metrics、NoData、multi-region de-dup は未実装。

### Inference

既存 inference は共通 preprocessing、512-pixel tiling、edge padding、overlap logits 平均、9-class argmax を実装し、入力 RGB の width/height/CRS/transform を出力へ保持する。prediction output に明示的 NoData はないため、prediction value 0 は必ず Background として扱い、NoData と解釈しない。

### Metric rules

`valid_gt_mask` は GT dataset mask がvalid、declared NoDataではない、valueが0–8の積集合とする。`semantic_gt_mask = valid_gt_mask & (gt >= 1)` とする。

- 9×9 confusion と Background diagnostics: `valid_gt_mask`
- primary class metrics、mIoU-8: classes 1–8
- Pixel Accuracy: `semantic_gt_mask`
- prediction 0: valid Background prediction
- modelごとに異なる prediction NoData: formal run failure

Absent class:

- `GT support == 0`: IoU/Recall = NA、FPとprediction supportは保持、macro対象外
- `GT support > 0 && prediction support == 0`: IoU/Recall = 0、Precision = NA
- minimum support thresholdは設けない
- CSVのNAは空欄とし、`undefined_reason` を併記する

`mIoU-8` は classes 1–8 のうち、その評価単位で `GT support > 0` の IoU だけを平均する。

Class-first Equal-region Macro は、まず class ごとに support がある region の IoU を等重み平均し、その8 class値を平均する。`mean(region mIoU)` は別のdiagnosticとして出す。

## D. De-duplication algorithm

### 1. Fail-closed preflight

predictionやGT classを参照する前に、GT geometryのみから次を検証する。

1. boundsが面積を持って交差するtile pairを列挙する（edge contactのみはoverlapでない）。
2. overlapping tileのCRS equalityを確認する。異なればFAILし、reprojectしない。
3. affine `b == 0`、`d == 0`、`a > 0`、`e < 0` をtolerance付きで要求し、rotation/shearを拒否する。
4. pixel width/height equalityを明示toleranceで確認する。
5. deterministic canonical originを `min(left), max(top)` とする。
6. 各tileのoffset候補をroundしてinteger化する。
7. integer offsetからleft/top/right/bottomを再構成し、metadataとの差がtolerance内であることを確認する。
8. 一つでもFAILならde-dupとformal comparisonを中止する。GTをresample/nearest-neighbor整合しない。

toleranceは実装定数とrun manifestへ記録し、`np.isclose` defaultへ依存しない。

### 2. Canonical pixel identity

preflight PASS後だけ、各pixelを次の整数で表す。

```text
global_row = tile_row_offset + local_row
global_col = tile_col_offset + local_col
pixel_key = (global_row, global_col)
```

world-coordinate文字列やfloat tupleをidentityに使用しない。内部表現は2列のsigned int64 structured arrayを推奨する。

### 3. Memory-safe grouping

Python object dictへ全pixelを保持せず、tile windowごとに固定dtype recordを生成する。

```text
canonical_row, canonical_col, gt_class, tile_index,
local_row, local_col, interior_distance, region_index
```

chunk sort後、必要ならtemporary binary filesをexternal mergeし、canonical key単位にstream group-byする。これによりfull raster stackを保持せずdeterministicに処理できる。

### 4. GT_CONFLICT

同一keyのvalid GT class集合を比較する。

- 1種類: consistent overlap
- 2種類以上: `GT_CONFLICT`
- class 0もvalid classとして判定に含める
- conflict pixelはregion/global dedup metricとformal comparisonsから除外
- class combinations、regions、tilesをQCへ記録

### 5. Geometry-only owner

consistent overlapの各observationで次を計算する。

```text
interior_distance = min(
  local_col,
  width - 1 - local_col,
  local_row,
  height - 1 - local_row
)
```

最大distanceをownerとし、tieは固定ValArea numeric suffix orderingで決める。owner APIへprediction、GT class、checkpoint、confidenceを渡さない。同じimmutable owner mapとcanonical key orderをA/B/C/Dへ適用し、owner map hashを記録する。

### 6. Aggregation surfaces

- Tile-level: 各tileを独立評価。overlapを含むdiagnostic。
- Global raw: 全tile confusionを単純加算。overlapを許容。
- Region-level de-duplicated: common owner mapでowner tileのregionへpixelを帰属する案を推奨。
- Global de-duplicated: consistent/non-conflict keyを1回だけ評価するprimary surface。
- Formal transitions/correction/regression: Global de-duplicated key setのみ。

## E. CLI proposal

```bash
python -m tools.evaluation.evaluate_gt54 \
  --manifest manifests/val_gt_georef.csv \
  --dataset-root /path/to/gsi_val_gt54 \
  --model-a /path/to/original_base.pth \
  --model-b /path/to/paddy_only.pth \
  --model-c /path/to/paddy_water.pth \
  --model-d /path/to/paddy_water_road.pth \
  --output-dir /path/to/gt54_evaluation_run
```

optional:

```text
--device cpu|cuda
--overlap 128
--prediction-cache-dir PATH
--reuse-predictions
--top-transitions 10
--work-dir PATH
--overwrite
--fail-fast
```

`dataset-root` は既存 layout `manifest.csv`, `rgb_images/<ValArea>.tif`, `labels/<ValArea>.tif` を使う。local manifestを信用するだけでなく、evaluator自身がmetadata/hash/alignmentを再検証する。checkpoint SHA256はprotocol expected hashと照合し、default mismatchをhard failureとする。

model別 overlap/preprocessing/mask/owner、automatic GT reprojection、class remapping、default sieve は許可しない。

## F. Output schema proposal

全CSVに `schema_version`, `run_id` を持たせ、model A/B/C/D、class 0–8、region、ValAreaのrow orderingを固定する。NAは空欄とし、定義可否列を持つ。

### Summary

- `evaluation_summary.csv`: status、protocol version、item/region count、preflight status、owner hash、dedup/conflict counts、timestamps
- `model_summary.csv`: model/hash、scope、region、valid/semantic pixels、Pixel Accuracy、mIoU-8、Equal-region Macro、Mean Regional mIoU

### Class metrics

対象ファイル:

- `global_deduplicated_class_metrics.csv`
- `global_raw_class_metrics.csv`
- `region_class_metrics.csv`
- `tile_class_metrics.csv`

主要列:

```text
model_id, scope, region, valarea, class_id, class_name,
tp, fp, fn, gt_support, prediction_support,
iou, precision, recall,
iou_defined, precision_defined, recall_defined, undefined_reason
```

### Confusion

`confusion_global_deduplicated.csv`, `confusion_global_raw.csv`, `confusion_by_region.csv` は long form で各unit 81行を保持する。

```text
model_id, scope, region,
gt_class_id, gt_class_name,
prediction_class_id, prediction_class_name, pixel_count
```

### Comparisons

- `model_comparison_metrics.csv`: before/after、class、before/after/delta IoU・Precision・Recall
- `correction_regression.csv`: GT class、5 categories、net change、corrected/regressed/net rates
- `prediction_transitions.csv`: before/after class、counts、rates、fixed flag、top rank
- `gt_conditioned_transitions.csv`: GT/before/after、change category、count

正式pairは必ず A→B、A→C、A→D、B→C、C→D の5組とする。

### QC

- `dataset_qc.csv`: paths、hashes、bands、grid、NoData、class validity、alignment
- `grid_preflight_qc.csv`: overlapping pair、CRS/pixel/rotation/phase/lattice、offset/residual、failure
- `overlap_qc.csv`: unique/single/overlap/consistent/conflict/evaluated counts
- `gt_conflict_pixels.csv`: canonical integer key、class combination、regions、ValAreas
- `owner_map_summary.csv`: owner tile別counts、tie counts、rule version、owner hash

巨大なpixel-by-pixel owner CSVは避け、必要ならlocal compact binary artifactを別途保存する。

## G. Test plan

実data、checkpoint、networkを使わずsmall synthetic GeoTIFFで検証する。

### Unit tests

- absent class: GT/prediction supportの各組合せ、FP保持、macro exclusion
- Background: 0→0、0→semantic、semantic→0、9×9 confusion保持、primary分母除外
- NoData: metadata 255、mask band、0との区別、model別prediction mask差異のfailure
- mIoU-8: class 0除外、present classのみ平均
- class-first Equal-region Macro: `mean(region mIoU)` と異なるfixture
- correction/regression: 5 categoryを各1pixel含み、mutually exclusive/exhaustiveを確認
- transition: 9×9、9×9×9、fixed 6、deterministic top 10

### Grid/de-dup tests

- perfectly aligned overlap → PASS
- GT-consistent overlap → 1 canonical pixel
- GT_CONFLICT（0対1を含む）→ metric exclusion
- owner tie → fixed ValArea ordering
- prediction/GT classを変えてもowner不変
- half-pixel grid phase mismatch → FAIL
- pixel size mismatch → FAIL
- rotation/shear → FAIL
- tolerance内metadata noise → PASS、超過 → FAIL
- edge contactのみ → overlap 0

### Integration tests

- 2 region、3–4tile、4 modelのsynthetic end-to-end
- raw count > dedup count
- region/global count conservation
- 全modelで同一owner/key hash
- required CSV presence/schema/order
- preflight FAIL時はnon-zero、QCのみ、dedup resultなし
- checkpoint hash mismatch、53 items、7 regions、duplicate ValArea、misalignmentを拒否

## I. Open questions / risks

実装前に次を確定する。勝手に仮定しない。

1. **GT NoData**: 実assetのnodata/mask band、0がnodata指定された例の有無。
2. **Prediction NoData**: external cacheでNoDataを許すか。推奨はformal runでは許さない。
3. **Raw vs sieve**: formal metricはraw argmaxを推奨するが仕様確認が必要。
4. **CRS scope**: 全54枚が同一CRS/common latticeか。異CRS non-overlap groupを `(crs_group,row,col)` として許すか。
5. **Tolerance**: pixel size、phase、bounds residualの固定値。
6. **Cross-region overlap**: region-level pixel attribution。推奨はglobal owner tileのregion。
7. **Conflict rate denominator**: 推奨は `conflict unique pixels / overlap unique pixels`。
8. **Interior distance**: 推奨は0-based integer distanceだが明文化が必要。
9. **Tie ordering**: numeric ValArea suffix orderを推奨。
10. **GT absent時Precision**: predictionありなら0、predictionなしならNAを推奨するが明文化が必要。
11. **Class attribution**: correction/regressionはGT class conditionedとし、誤ったRoad流入はtransition側で示す。
12. **全region absent class**: Equal-region MacroをNAにし、0補完しない案を推奨。
13. **Preflight failure outputs**: summary/dataset/grid QCのみを出し、空のdedup CSVは作らない。
14. **Provenance wording**: GT54をindependent holdout/test/unseenとは呼ばない。
